# Standalone runtime

The Windows SEA executable embeds the compiled browser app, migration SQL, verified Cloudflare Tunnel binary, release metadata, and third-party license notices. It runs the same game API through two build aliases: `cloudflare:workers` becomes the local SQLite binding, and the hosted identity helper becomes an AsyncLocalStorage identity supplied only to the local teacher API. The single EXE can be copied without adjacent runtime files.

No OpenAI identity header is trusted. `/teacher` opens the dashboard directly without a password, setup code, or teacher session. Teacher pages and the `/teacher/api/game` API require both a loopback socket and loopback hostname and are never authorized through tunnel ingress. Only the teacher API receives local teacher identity; `/api/game` remains the student API even on localhost, including requests carrying an old teacher cookie. First-time classroom setup asks for the classroom name and teacher name once; subsequent visits restore the saved dashboard. There is one classroom: students open the student link and type their name and exactly four-digit PIN. Student PINs and session tokens remain hashed. An unknown name offers an explicit new-account step; account creation uses only the name and PIN and explains that students must reuse those credentials to retain progress. An incorrect PIN for an existing name directs the student to check the PIN or ask the teacher, preventing accidental duplicate accounts.

`SudokuData/classroom.sqlite` lives beside the executable, with SQLite WAL and full synchronization enabled. Student profiles, saved puzzles, scores, prizes, awards, and editable block avatars and their upgrades survive server restarts and sign-in on another device. The API's D1 batch calls run as synchronous SQLite transactions to preserve the game's `changes()` guards, exactly-once rewards, and coin balance checks. Schema migrations are tracked separately and applied transactionally. Stop the server before copying its data directory as a backup. The hosted Site and this local database are separate classrooms.

Runtime options: `--port 8787`, `--host 0.0.0.0`, `--data-dir PATH`, `--no-open`, `--offline`, `--tunnel`, `--cloudflared PATH`, `--help`, and `--version`. Compiled EXE startup enables the tunnel by default; `--offline` explicitly disables it. Developer runs outside SEA default to offline and additionally need `--assets web-assets.json --migrations migrations.json`. The static asset manifest is a map from URL path to `{content: base64, mime: contentType}`. Migration assets are `{name,sql}[]`.

Local network play remains available in both modes. Start the EXE with `--offline` when no internet connection is needed. The server shows IPv4 classroom links; students need a network route to this computer, and the Windows host must permit its listening port. These LAN addresses are not public internet links.

Default EXE startup extracts its embedded official Windows x64 tunnel helper into `SudokuData/runtime/cloudflared-<version>-<hash>.exe` and verifies its SHA-256 checksum before use. A cached helper is reused only when its bytes match the embedded release metadata. The build helper `download-cloudflared.mjs` obtains the release pinned by `cloudflared-release.json`; installed users do not need a separate download. `--cloudflared PATH` provides an explicit development or testing override. The old `Start-Sudoku-Online.cmd` remains compatible but is unnecessary. Online mode creates a temporary Cloudflare Quick Tunnel and displays its public HTTPS student link after connection. It needs internet but no Cloudflare account or domain. Its hostname changes on a new run; a permanent hostname needs a separately configured named tunnel and is not automated here.

The tunnel connects to a dedicated loopback listener that always treats requests as student traffic. Teacher identity and all `/teacher` routes remain unavailable on that listener, including requests with forged identity headers or old teacher cookies. The primary listener serves the direct dashboard only to the server computer. Teacher JSON writes retain same-origin checks; a remote student request cannot become a teacher request by changing its URL or headers. Tunnel requests use their validated public HTTPS origin for game origin checks and secure student cookies. Neither listener serves arbitrary files: only embedded web assets and the game's API are available; source files and classroom databases stay private.

`/api/server-info` reports the share origin, local and LAN origins, and tunnel status. The standalone client waits for this response before rendering, then updates Share classroom as the tunnel connects or fails. A requested but unavailable tunnel has no share origin; a LAN fallback is clearly labeled separately. Closing the server with Ctrl+C stops its managed tunnel too. The computer must remain awake and connected while remote students play. Both connection modes keep the app and SQLite database on this computer and use the same saved student accounts.
